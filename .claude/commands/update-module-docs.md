Given a module and (optionally) some context about its usage, you must create or update the documentation for it, 
following the instructions and templates defined in the knowledge base.

## Instructions

Follow these steps carefully:

### Step 1: Read the Guide

Get familiar with knowledge base structure and rules: [docs/kb/README.md](../../docs/kb/README.md)

### Step 2: Collect the info

Gather the existing information:
- existing documentation in the knowledge base
- current session
- details provided by user when giving you this task

Explore the source of truth:
- module code
- module configuration
- project configuration
- deployment configuration

### Step 3: Put if all together and prepare the plan

- Combine the acquired knowledge into a whole using the guidelines
- Compare you vision and gathered knowledge with existing documentation, if it exists
- Propose to the user all the updates, corrections and new files needed to make the documentation of the requested module fit the guidelines, in a compact form.

### Step 4: Update the documentation

After the permission is given, update the documentation, following the knowledge base guidelines and user's corrections, if provided.


## Golden Rules

- Always stick to the existing documentation patterns if not specified
- Try to make as less changes to the doc structure and content as you can. 
- Consult the user on whether the approach you want to apply is appropriate
