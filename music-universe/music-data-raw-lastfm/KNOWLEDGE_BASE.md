# Music Universe - LastFM Data Collector Knowledge Base

## Project Overview

This Spring Boot application collects data about tags, artists, albums, and tracks from the LastFM public API for further processing. It's part of a larger "Art Universe" project, specifically within the "Music Universe" domain.

## Architecture

### Core Components

1. **API Client Layer**
   - Handles communication with LastFM API
   - Manages API calls and responses
   - Implements rate limiting and retry mechanisms

2. **Data Processing Layer**
   - Processes API responses
   - Maps DTOs to entities
   - Handles attribute history and snapshots

3. **Persistence Layer**
   - Manages entity storage
   - Handles attribute history
   - Maintains entity relationships

4. **Scheduling Layer**
   - Coordinates API call generation
   - Manages API call execution
   - Schedules response processing

5. **Maintenance Layer**
   - Provides database cleanup utilities
   - Manages entity lifecycle

## Key Concepts

### Entity Types

The system works with four main entity types:
- **Artists** (`LastfmArtist`)
- **Albums** (`LastfmAlbum`)
- **Tracks** (`LastfmTrack`)
- **Tags** (`LastfmTag`)

These are represented by the `LastfmEntityType` enum.

### API Call Types

API calls are categorized by `LastfmApiCallType` enum.

### Attribute System

The system uses a flexible attribute system:
- `LastfmAttribute` enum defines available attributes (MBID, URL, RANK, etc.)
- Attributes can be entity-specific or relationship-specific
- Attributes have history (SCD2 - Slowly Changing Dimension type 2)
- Snapshots capture attribute state at specific points in time

### Data Processing Flow

1. API calls are generated by `LastfmApiCallGenerator` implementations
2. API calls are executed by `LastfmApiClient`
3. Responses are processed by `LastfmApiResponseProcessor` implementations
4. DTOs are mapped to entities by `EntityFactory` implementations
5. Attributes are extracted and stored by `EntityAttributeHandler` implementations
6. Entity relationships are created and maintained

Used for creating entities from DTOs:
- `LastfmArtistEntityFactory`

- `LastfmTrackEntityFactory`

- Request builders

## Key Classes and Their Purposes

### API Client Layer

- `LastfmApiClient`: Interface for making API calls to LastFM
- `LastfmApiClientImpl`: Implementation of LastFM API client
- `LastfmApiCall`: Entity representing an API call
- `LastfmApiResponse`: Entity representing an API response
- `LastfmApiCallType`: Enum of supported API call types
- `LastfmApiCallGenerator`: Base class for API call generators
- `LastfmApiCallService`: Service for managing API calls
- `LastfmApiResponseService`: Service for managing API responses

### Data Processing Layer

- `LastfmApiResponseProcessor`: Base class for processing API responses
- `LastfmApiDtoProcessor`: Processes DTOs and maps them to entities
- `EntityFactory`: Creates entities from DTOs
- `EntityAttributeHandler`: Extracts and sets attribute values
- `EntityMappingBuilder`: Builds mappings between DTOs and entities
- `EntityRelationBuilder`: Builds entity relationships
- `AttributeHistoryBuilder`: Builds attribute history records

### Entity Layer

- `BaseLastfmEntity`: Base class for all LastFM entities
- `LastfmArtist`: Entity representing an artist
- `LastfmAlbum`: Entity representing an album
- `LastfmTrack`: Entity representing a track
- `LastfmTag`: Entity representing a tag
- `LastfmEntityType`: Enum of entity types
- `LastfmEntityRelation`: Entity representing a relationship between entities
- `LastfmAttribute`: Enum of entity attributes
- `LastfmAttributeHistoryRecord`: Entity representing attribute history
- `LastfmAttributeSnapshot`: Entity representing attribute snapshot
- `LastfmDataSnapshot`: Entity representing data snapshot

### Service Layer

- `LastfmArtistService`: Service for artist operations
- `LastfmAlbumService`: Service for album operations
- `LastfmTrackService`: Service for track operations
- `LastfmTagService`: Service for tag operations
- `LastfmEntityService`: Service for common entity operations
- `LastfmEntityRelationService`: Service for entity relationship operations
- `LastfmAttributeHistoryService`: Service for attribute history operations
- `LastfmAttributeSnapshotService`: Service for attribute snapshot operations
- `LastfmDataSnapshotService`: Service for data snapshot operations

### Scheduling Layer

- `LastfmApiCallScheduler`: Schedules API call generation and execution
- `LastfmApiResponseProcessingScheduler`: Schedules API response processing

### Maintenance Layer

- `DbMaintenanceService`: Service for database maintenance
- `DbMaintenanceCoordinator`: Coordinates database maintenance tasks

## Database Schema

The database schema includes:
- Entity tables (`artist`, `album`, `track`, `tag`)
- API tables (`api_call`, `api_response`)
- Attribute tables (`attribute`, `attribute_history`, `attribute_snapshot`)
- Relationship tables (`entity_relation`)
- Snapshot tables (`data_snapshot`)
- Maintenance tables (`cleanup_run`, `cleanup_history`)

## Configuration

## Naming Conventions

1. **Entity Classes**
   - Prefix: `Lastfm`
   - Suffix: Entity type (e.g., `Artist`, `Album`)
   - Example: `LastfmArtist`

2. **Repository Classes**
   - Prefix: Entity name
   - Suffix: `Repository`
   - Example: `LastfmArtistRepository`

3. **Service Classes**
   - Prefix: Entity name
   - Suffix: `Service`
   - Example: `LastfmArtistService`

4. **Service Implementations**
   - Prefix: Entity name
   - Suffix: `ServiceImpl`
   - Example: `LastfmArtistServiceImpl`

5. **API Processors**
   - Prefix: `Lastfm`
   - Middle: API call type
   - Suffix: `ResponseProcessor`
   - Example: `LastfmArtistGetInfoResponseProcessor`

6. **API Call Generators**
   - Prefix: `Lastfm`
   - Middle: API call type
   - Suffix: `ApiCallGenerator`
   - Example: `LastfmTagTopTagApiCallGenerator`

7. **Entity Factories**
   - Prefix: `Lastfm`
   - Middle: Entity type
   - Suffix: `Factory`
   - Example: `LastfmArtistEntityFactory`

8. **DTOs**
   - Prefix: API call type or entity type
   - Suffix: `Dto`
   - Example: `ArtistGetInfoArtistDto`

## Common Patterns

1. **Entity Processing Flow**
   - Generate API calls
   - Execute API calls
   - Process API responses
   - Map DTOs to entities
   - Extract and store attributes
   - Create entity relationships

2. **Attribute History**
   - Attributes are stored with validity periods
   - New attribute values create new history records
   - Old attribute values are expired

3. **Entity Relationships**
   - Relationships are stored in `entity_relation` table
   - Relationships are bidirectional
   - Relationships are created during response processing

4. **Data Snapshots**
   - Snapshots capture data state at specific points in time
   - Snapshots are used for attribute history

5. **API Call Generation**
   - API calls are generated based on entity state
   - API calls are prioritized and executed
   - API responses are processed asynchronously

## Important Interfaces and Abstract Classes

1. **EntityFactory**: Creates entities from DTOs
2. **EntityAttributeHandler**: Extracts and sets attribute values
3. **LastfmApiResponseProcessor**: Base class for processing API responses
4. **LastfmApiCallGenerator**: Base class for generating API calls
5. **BaseLastfmEntity**: Base class for all LastFM entities
