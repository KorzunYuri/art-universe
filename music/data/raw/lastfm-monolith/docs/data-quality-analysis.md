# Анализ качества данных по популярности сущностей

## Обзор

Данный отчет анализирует качество собранных данных в продовой базе данных с точки зрения популярности сущностей. Анализ проводился на основе лимитов, заданных в конфигурации приложения, и наличия статистики популярности в ответах API методов LastFM.

## Лимиты из конфигурации (application.yml)

```yaml
lastfm:
  threshold:
    artist:
      listenersCount: 1000
    album:
      playCount: 10000
    track:
      playCount: 10000
    tag:
      usageCount: 1000
```

## Детальный анализ проблем

### 1. Анализ использования фильтрации

#### Методы С фильтрацией по популярности:
- **ARTIST_TOP_TRACKS**: ✅ Фильтрует треки по `listeners ≥ 1,000` (результат: 0.1% треков ниже лимита)
- **ARTIST_TOP_ALBUMS**: ✅ Фильтрует альбомы по `playcount ≥ 10,000` (результат: 0.006% альбомов ниже лимита)
- **ARTIST_TOP_TAGS**: ✅ Фильтрует теги по `usage_count ≥ 10` (но не по основному лимиту 1,000)
- **ARTIST_GET_SIMILAR**: ✅ Фильтрует по `match score ≥ 0.2` (результат: 10.3% артистов ниже лимита)
- **ARTIST_SEARCH**: ✅ Фильтрует по схожести имени `≥ 0.5`

#### Методы БЕЗ фильтрации (критические проблемы):
- **ALBUM_GET_INFO**: ❌ Нет фильтрации → 94.1% артистов и 100% треков ниже лимита
- **ARTIST_GET_INFO**: ❌ Нет фильтрации → 23.0% артистов ниже лимита
- **TAG_TOP_ARTISTS**: ❌ Нет фильтрации → 14.9% артистов ниже лимита
- **TAG_TOP_TRACKS**: ❌ Нет фильтрации → 17.6% артистов и 21.1% треков ниже лимита
- **TAG_TOP_TAGS**: ❌ Нет фильтрации (но все теги качественные)
- **TRACK_GET_INFO**: ❌ Нет фильтрации → 66.7% артистов, 98.5% альбомов и 64.2% треков ниже лимита

### 2. Критические источники непопулярных данных

#### Альбомы
- **TRACK_GET_INFO**: 98.5% альбомов ниже лимита (2,684 из 2,724)
  - Проблема: API не возвращает статистику для альбомов в track.getInfo
  - Решение: Добавить вызовы album.getInfo для обогащения данных
- **ALBUM_GET_INFO**: 6.4% альбомов ниже лимита (10 из 156)
  - Статус: Приемлемый уровень качества

#### Треки
- **ALBUM_GET_INFO**: 100% треков без статистики (86,079 треков)
  - Проблема: API не возвращает статистику для треков в album.getInfo
  - Решение: Добавить вызовы track.getInfo для обогащения данных
- **TRACK_GET_INFO**: 64.2% треков ниже лимита (2,488 из 3,874)
  - Проблема: Низкокачественные треки попадают в систему
  - Решение: Применить фильтрацию на этапе обработки
- **TAG_TOP_TRACKS**: 21.1% треков ниже лимита (7,009 из 33,270)
  - Проблема: API не возвращает статистику популярности
  - Решение: Применить фильтрацию после обогащения данными

#### Артисты
- **ALBUM_GET_INFO**: 94.1% артистов ниже лимита (1,815 из 1,929)
  - Проблема: API не возвращает статистику для артистов
  - Решение: Добавить вызовы artist.getInfo для обогащения данных
- **ARTIST_GET_INFO**: 23.0% артистов ниже лимита (14,297 из 62,133)
  - Проблема: Низкокачественные артисты попадают в систему
  - Решение: Применить более строгую фильтрацию
- **TAG_TOP_TRACKS**: 17.6% артистов ниже лимита (565 из 3,216)
- **TAG_TOP_ARTISTS**: 14.9% артистов ниже лимита (2,713 из 18,205)

#### Теги
- **Все методы кроме TAG_TOP_TAGS**: 99-100% тегов без статистики
  - Проблема: Только tag.getTopTags возвращает статистику использования
  - Решение: Использовать только теги из tag.getTopTags или добавить tag.getInfo

### 3. Методы без статистики популярности

#### Полностью без статистики:
- **TAG_TOP_ARTISTS**: Создает артистов без данных о популярности
- **TAG_TOP_TRACKS**: Создает треки и артистов без данных о популярности
- **ARTIST_GET_SIMILAR**: Создает артистов только с match score

#### Частично без статистики:
- **ALBUM_GET_INFO**: Создает треки, артисты и теги без статистики
- **TRACK_GET_INFO**: Создает альбомы, артисты и теги без статистики
- **ARTIST_GET_INFO**: Создает теги без статистики
- **ARTIST_TOP_ALBUMS**: Создает артистов без статистики
- **ARTIST_TOP_TRACKS**: Создает артистов без статистики

## Архитектурные улучшения

### 1. Двухэтапная обработка
- **Этап 1**: Создание сущностей без статистики
- **Этап 2**: Обогащение статистикой и применение фильтров
- **Этап 3**: Удаление сущностей, не прошедших фильтрацию

### 2. Каскадная фильтрация
- При создании трека/альбома проверять популярность связанного артиста
- Если артист непопулярен, не создавать зависимые сущности

### 3. Интеллектуальная фильтрация
- Использовать комбинацию метрик (listeners + playcount + rank)
- Применять разные пороги для разных источников данных
- Учитывать контекст (популярные теги vs нишевые жанры)
